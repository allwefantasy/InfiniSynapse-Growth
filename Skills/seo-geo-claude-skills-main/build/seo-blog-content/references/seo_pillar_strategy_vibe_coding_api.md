# SEO Pillar Strategy for Vibe Coding Users → API/Data Infra Adoption

## 1. Executive Summary

This is the **expanded second-pass SEO plan** built from the existing keyword database.

Compared with the prior version, this revision does two things:

1. **Expands every pillar to 15–20 articles**
2. **Upgrades the keyword pool to higher-value terms with `KD < 50`**

At the same time, it keeps the stricter product-fit rule:

> If a topic cannot smoothly lead a vibe-coding user toward API capability, data access, orchestration, or production readiness, it should not be a pillar topic.

### Keyword selection rules used in this version

- **KD < 50** only
- Prefer **higher search volume** and/or **higher commercial value**
- Keep only topics that can bridge into:
  - API integration
  - tool calling / agent workflows
  - data API usage
  - backend / production readiness
- Avoid reintroducing broad off-topic vertical clusters unless the topic clearly helps product adoption

---

## 2. Strategic Logic

The final structure still follows the same product-adoption path:

1. **Teach safer vibe-coding workflows**
2. **Help users choose the right stack / app builder**
3. **Show how prototypes connect to APIs**
4. **Show how AI becomes callable workflows**
5. **Show how data/API systems become production-ready**

This means the SEO system is not just traffic-oriented.
It is designed to move users from:

> “I can vibe code a prototype” → “I need real API and data infrastructure underneath it.”

## 4. Recommended Publishing Priority

If the goal is not just traffic but **smooth product entry**, publish in this order:

1. **Pillar 3 — API Integration for Vibe-Built Products**
2. **Pillar 4 — Tool Calling and Agent Workflows**
3. **Pillar 5 — Data APIs and Production Readiness**
4. **Pillar 2 — Stack and App Builder Selection**
5. **Pillar 1 — Workflow Discipline for Vibe Coding**

### Why this order works

- **Pillars 3–5** are closest to product intent and monetizable adoption
- **Pillars 1–2** attract larger top-of-funnel traffic and then feed users into deeper integration and infrastructure needs
