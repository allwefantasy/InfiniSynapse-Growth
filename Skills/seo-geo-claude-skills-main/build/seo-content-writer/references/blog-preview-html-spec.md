# Blog Preview HTML Spec (Local Review)

Standard for generating **`preview.html`** pages from SEO blog bundles. Previews let editors and frontend engineers review the full article — meta tags, schema, hero, body images, and Markdown rendering — in a browser **before** CMS deployment.

**Reference implementation**: `SEO/Blog/pillar1-ai-native-data-analysis/build-preview.py` (InfiniSynapse Pillar 1).

**Related**: [Blog Hero Cover Spec](blog-hero-cover-spec.md) for hero image rules.

---

## Purpose

| Use preview for | Do **not** use preview for |
|-----------------|----------------------------|
| Editorial sign-off (copy, headings, FAQ) | Production URL or canonical host |
| Frontend layout spot-check | Final site CSS / nav / footer |
| Meta + schema package review | Replacing CMS render pipeline |
| Hero and body image path verification | SEO indexing (add `noindex` not required — file is local-only) |

Every preview page must show a visible **LOCAL PREVIEW** banner so it is never mistaken for production.

---

## Output Files

| File | Location | Description |
|------|----------|-------------|
| `preview.html` | Each article folder `{nnn}-{slug}/` | Single-article full preview |
| `INDEX-preview.html` | Blog pillar / bundle root | Linked list of all `preview.html` pages |

**Do not deploy** `preview.html` or `INDEX-preview.html` to production. They are dev/review artifacts only (same class as `audit.md`).

---

## Input Files (Per Article)

| File | Role in preview |
|------|-----------------|
| `article.md` | Markdown source → HTML body |
| `meta-tags.html` | Injected into `<head>` (HTML comments stripped) |
| `schema.json` | Wrapped in `<script type="application/ld+json">` |
| `images/*.png` | Referenced via relative paths from `article.md` |

Optional: if `meta-tags.html` or `schema.json` is missing, still emit preview with body only.

---

## Markdown → HTML Rules

### Strip before render

Remove CMS-only lines from `article.md` (keep H1, byline, hero image, TOC, body):

- `**Meta Description**:`
- `**Slug**:`
- `**Target keyword**:`
- `**Secondary**:`

### Converter extensions

Use Python `markdown` with:

- `tables`
- `fenced_code`
- `nl2br` (optional)
- `TocExtension` with **slugify** on headings so TOC anchors match production (`#tldr`, `#frequently-asked-questions`, etc.)

### Heading IDs

Slugify pattern: lowercase, hyphens, strip punctuation — must match frontend anchor contract in `DEPLOY.md` Step A.

## Preview HTML Structure

```html
<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="utf-8">
  <!-- meta-tags.html (no comment blocks) -->
  <style>/* preview-only article CSS */</style>
  <script type="application/ld+json">/* schema.json array */</script>
</head>
<body>
  <div class="preview-banner">LOCAL PREVIEW · Not for production · …</div>
  <header><a href="../INDEX-preview.html">← All previews</a></header>
  <article class="blog-post"><!-- rendered article.md --></article>
  <footer class="preview-meta">Source: {folder}/article.md · Generated by build-preview.py</footer>
</body>
</html>
```

### Required UI elements

| Element | Requirement |
|---------|-------------|
| **Banner** | Sticky top bar, high-contrast, states LOCAL PREVIEW + not for production |
| **Nav link** | Back to `INDEX-preview.html` at pillar root |
| **Article** | Max-width ~860px, readable typography, styled tables/blockquotes |
| **Images** | `max-width: 100%`, relative `images/` paths work under `file://` |
| **Footer** | Source path + generator name |

### Preview CSS (minimal)

- System sans-serif, 17px body, comfortable line-height
- H2 with accent underline; tables with borders
- Distinct from production site theme — preview CSS is **bundle-local**, not shared site CSS

---

## Index Page (`INDEX-preview.html`)

Generated at bundle root. Contains:

- Title: `{Pillar name} · Article Previews (N)`
- Note: local review only, not production
- Unordered list: `{folder}/preview.html` linked with folder slug + H1 from first line of `article.md`

Scan pattern for article folders: `[0-9][0-9][0-9]-*` directories containing `article.md`.

---

## Regeneration Triggers

Re-run preview generation after any change to:

- `article.md` (copy, headings, images, links)
- `meta-tags.html`
- `schema.json`
- Hero or body PNGs under `images/`
- H1 title (also update hero per [blog-hero-cover-spec.md](blog-hero-cover-spec.md))

### Suggested full bundle pipeline

```bash
python3 build-visuals.py          # hero + body HTML
bash render-all-images.sh         # PNGs + og-cover.png
python3 build-preview.py          # preview.html + INDEX-preview.html
```

When porting to a **new** pillar, copy `build-preview.py` and adjust `PILLAR` path + index title string.

## QA Checklist

- [ ] Every article folder with `article.md` has `preview.html`
- [ ] `INDEX-preview.html` lists all articles; links resolve
- [ ] LOCAL PREVIEW banner visible on every page
- [ ] `<head>` contains stripped `meta-tags.html` tags
- [ ] `schema.json` present as `application/ld+json` when file exists
- [ ] Hero image loads (first `<img>` in article)
- [ ] Body diagram images load (relative `images/` paths)
- [ ] TOC anchor links jump to correct H2 sections
- [ ] CMS metadata lines (`**Slug**:`, etc.) **not** visible in rendered body
- [ ] Internal links `/blog/{slug}` render as expected (may 404 locally — acceptable)

## Bundle File Matrix

| File | Ship to production? | In preview? |
|------|----------------------|-------------|
| `article.md` | Yes (via CMS) | Rendered in `<article>` |
| `meta-tags.html` | Yes (`<head>`) | Injected in `<head>` |
| `schema.json` | Yes (`<script>`) | Injected in `<head>` |
| `images/*.png` | Yes (CDN) | Relative refs in body |
| `preview.html` | **No** | Output |
| `INDEX-preview.html` | **No** | Output |
| `audit.md` | No | No |
| `README.md` | No | No |
| `visuals/*.html` | No (source only) | No |
