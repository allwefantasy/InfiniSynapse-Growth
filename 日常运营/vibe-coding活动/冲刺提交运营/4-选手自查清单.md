# 参赛作品自查清单（提交前对照）

> 用途：发给选手，交卷前自己过一遍。很多作品不是不行，是不知道评委看什么。
> 对照大赛「前置准入条件 + 评分维度」整理。全部打勾再提交，通过率和分数都会更高。

---

## 一、前置准入（必须全满足，否则直接出局）

- [ ] **是可运行的应用**：Web / 移动 App / 小程序 / 桌面应用之一；不是纯脚本、命令行工具或 Jupyter Notebook。
- [ ] **已部署上线**：有公网可访问的 URL（或可下载安装包），评委能直接打开使用。
- [ ] **真的集成了 InfiniSynapse**：后端通过 Server API 发起分析任务，调用日志在平台后台可查验。
- [ ] **有明确使用场景**：一句话能说清「谁、在什么情况下、用它解决什么问题」。

> 这四条是「合格线」。做到，你就已经超过一半半途而废的人。

---

## 二、提交材料清单（缺一项都可能影响评审）

- [ ] 应用名称与简介（含使用场景说明）
- [ ] 可访问的作品地址（公网 URL 或安装包下载地址）
- [ ] InfiniSynapse API 集成说明（用在哪个环节、调了什么）
- [ ] 代码仓库地址（可选，但建议放，利于加分）

---

## 三、拉开差距的加分项（想冲名次看这里）

**场景与价值**
- [ ] 场景足够聚焦，不贪大而全，一个痛点解决透
- [ ] 目标用户明确，能说出「为什么他会用」

**功能完成度**
- [ ] 核心流程完整跑通，不半路报错
- [ ] 对空输入 / 异常数据有基本处理，不白屏

**AI / 数据能力体现**
- [ ] 分析结果真实有用，不是套壳摆设
- [ ] 用上了图表 / 表格等结构化输出，结论可读
- [ ] （可选）配置了知识库，提升语义理解准确度

**体验与观感**
- [ ] UI 干净能看，排版不乱（观感差是常见丢分点）
- [ ] 移动端能正常打开使用
- [ ] 首屏能让人 3 秒看懂「这是做什么的」

**可信度**
- [ ] 有真实可操作的 demo 数据 / 示例，评委不用自己造数据就能体验

> 注意：评审**不以 GitHub 下载量或 Star 数**为依据，别刷这些。

---

## 四、交卷前最后 3 件事

1. **换个设备/无痕窗口打开你的线上地址**，确认别人真的能访问（别只在本地跑通就交）。
2. **自己走一遍完整流程**，从进入到出结果，卡壳的地方现在补。
3. **想让人帮你把关？** 截止前可申请一次官方 1v1 review——群里回复「review」预约。

---

提交后仍可在截止前迭代更新，直接在原作品上改即可，无需重新提交。
