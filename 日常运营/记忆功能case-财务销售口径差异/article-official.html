但每次有人去问 AI Agent ："帮我看一下 Q1 营收"，得到的永远是其中一个数字——更糟的是，Agent 还要先问你一遍："你要的是哪一种？" 或者干脆默认按某一种算完了，然后等你纠正："不对不对，你算的是 cash basis ，我要的是合同口径。"

这就是今天大多数 "AI for analytics" 工具的天花板：Agent 没有关于这个数据源的业务记忆。它每次都从零开始猜，每次都要你重新讲一遍口径。讲一万次，下一次新会话，它还是会再问你一遍。

InfiniSynapse 这次上线的数据源记忆功能，把这件事彻底改了——业务口径不再绑在某一次会话上，而是绑在数据源本身。同一个数据源下，任何人、任何新会话、任何 Agent ，第一次问就自动加载你之前定下的所有口径。

下面用一次真实的录屏对比讲透：同样一句话，"沉淀前"和"沉淀后"的 Agent 行为差了多远。

场景：同一份数据，两套口径，差 85 万

数据是一个非常典型的 SaaS 销售场景，两张表：

deals——销售侧的交易表，关键字段 deal_amount / close_date / deal_stage
payments——财务侧的回款表，关键字段 payment_amount / payment_date

业务上这是同一笔生意的两个面：

销售口径（ Sales ）：SUM(deals.deal_amount) WHERE close_date ∈ period AND deal_stage = 'closed-won'——只要合同签了、状态走到 closed-won，就算这个季度的营收
财务口径（ Finance ）：SUM(payments.payment_amount) WHERE payment_date ∈ period——钱实际打进账户才算

Q1 跑下来，销售口径 410 万、财务口径 325 万、差 85 万。两个数字都对，业务上一个看签单速度、一个看回款健康度，必须同时摆出来才完整。但要让 Agent 自动并列出这两个数字，传统做法每次都得手把手教。

任务 A · 沉淀前： Agent 从零探查 + 用户必须纠正 + 8 分 23 秒

打开 任务 A 的回放链接[1]，用户的问题极简单：

Let's calculate the revenue in the first quarter.

按下回车之后， Agent 立刻开始它的"摸底之旅"。在这条任务里它一共调了 12 个工具步骤，前 6 步全是"我先搞清楚这个数据源里有什么"：列表名、看表结构、 profile 字段分布、检查 deal_stage 都有哪些枚举值、看 payment_date 的时间跨度……

这是 AI Agent 在面对陌生数据源时的标准动作，也是 InfiniSynapse 一直坚持的做法——宁可慢一点，也要把 schema 摸清楚再算。这件事本身没错，错的是每一次新会话都要从零摸一遍。

更扎心的还在后面。摸完底之后， Agent 默认选了 cash basis（按到账算），跑出了一个 325 万的数字。用户一看就知道不对，必须主动纠正：

Revenue calculations thereafter are all defined as the amount of transactions already completed.

Agent 接到纠正后重新算，最终输出 410 万——但这一轮总耗时 8 分 23 秒、12 个工具步骤、1 次用户纠正。而且最终只输出了一个口径的数字，那个本该并列的 325 万被丢掉了。

如果到这里就结束，那只是又一次"AI 工具用一次就完"的失忆循环。下个月再做 Q1 复盘的人——可能是另一个同事、也可能是你自己——会原原本本再走一遍这 8 分 23 秒。

中场：把两套口径"沉淀"进数据源记忆

任务 A 结束的那一刻，用户做了一件以前在大多数 AI 工具里没法做的事——打开数据源详情页，进入"记忆"面板，把刚才教 Agent 的两套口径，以业务规则的形式写进去。

写入的内容非常简洁，每条规则只有一句 SQL 语义的定义 + 一个 ACTIVE 状态：

// sales revenue
Sales = SUM(deals.deal_amount)
        WHERE close_date ∈ period
          AND deal_stage = 'closed-won'                  ACTIVE

// finance revenue
Finance = SUM(payments.payment_amount)
          WHERE payment_date ∈ period                    ACTIVE

这一步是整个流程里最关键也最容易被低估的设计——

它不是把对话存起来。聊天记录式的"记忆"在过去两年里被各种工具反复尝试过，结论是它完全帮不到下一次会话——上次的对话很长很乱， Agent 没有能力从一堆自然语言里准确抽出"那个时候我们到底定了什么口径"。

它也不是把答案存起来。把 "Q1 营收 = 410 万" 这个数字存进去，下个月数据更新了，这个数字就过期了。

它是把"算法"和"业务定义"存起来。两条规则结构化、可执行、和数据源绑定。下次任何人在这个数据源上问任何关于"营收"的问题， Agent 在 plan 阶段就会自动加载这两条规则——不需要 prompt 里写 "recall"，不需要给上下文，自动。

这就是"数据源记忆"和聊天历史的本质差异——聊天历史绑用户、绑会话；数据源记忆绑数据本身。

任务 B · 沉淀后：同一句话、 Agent 自动并列双口径 + 主动校验 + 2 分 48 秒

切到一个全新会话，输入和任务 A 一字不差的同一句话：

Let's calculate the revenue in the first quarter.

打开 任务 B 的回放链接[2]，可以看到这次 Agent 的开场行为完全变了——它没有像任务 A 那样去 list 表、 check 字段枚举，而是直接进入算数环节：两套规则被同时加载，并行计算。

更让人意外的是它主动做了一件任务 A 里完全没做的事——交叉校验。在两个数字算出来之后， Agent 自己规划了一个额外的步骤："既然销售口径 410 万、财务口径 325 万，那回款率是多少？这 325 万里有多少是 Q1 内签 Q1 内回的、又有多少是上个季度的合同跨到 Q1 才回的？"

最终任务 B 输出的不是一个数字，而是四个维度并列的完整业务画像：

Operational Q1 revenue (cash basis): 3,250,000
Q1 bookings (closed-won): 4,100,000
Collection rate: 48.78%
Pre-Q1 carry-over: 1,250,000 · In-Q1 collected: 2,000,000

总耗时 2 分 48 秒、15 个工具步骤、0 次用户纠正。注意——步骤反而多了 3 步，但这 3 步全是 Agent 主动追加的交叉校验，不是任务 A 那种"从零探查"的浪费。

这就是"数据源记忆"真正在改变的东西——它不是把 Agent 变成一个更快的执行工具，而是把每一个 Agent 都变成"已经熟悉你业务的老员工"。新员工第一天上班的所有"摸底成本"，被沉淀的口径一次性付清。

沉淀一次，跨会话、跨用户、跨时间生效

记忆写进数据源之后，它的服务半径远远不止"下次同一个人再问同一个问题"。它的真正价值在于三个方向的自动复用——

跨会话生效：明天、下个月、明年的任何一次新会话，只要落在这个数据源上，两套口径都自动加载。无需 prompt 里写 "Recall"，无需 attach 历史对话，无需任何人工干预。

跨用户一致：组里其他人——不管是新来的实习生、隔壁部门的产品经理、还是临时接手的轮岗同事——在这个数据源上第一次问"Q1 营收"， Agent 给出的就是双口径并列那一份。再也不会出现"销售口径和财务口径吵 85 万"这种内部沟通成本。

跨时间稳定：数据每天都在变，但口径不变。两条规则是结构化定义而不是某次跑出的具体数字，所以无论 Q1 数据怎么更新、明年再回头跑同一个季度，规则永远适用。口径一旦定下，就再也不漂。

写在最后

如果你正在用 AI Agent 跑数据分析，不妨问自己一个问题——

过去三个月，你一共花过多少时间，重复跟 Agent 解释那几条业务口径？

我们见过的极端例子是，一个数据团队每次月会前都要花两小时反复对齐"这个指标到底按哪种算法"，对齐完之后 prompt 一关、 AI 一忘、下个月再来。一年下来这个数字非常可观。

InfiniSynapse 数据源记忆要解决的就是这件事——把口径从"每次会话里的临时上下文"，升级成"数据源自带的业务知识"。沉淀一次，跨会话、跨用户、跨时间永久生效。 Agent 再问就自动加载。

具体到产品上，我们提供：

业务规则结构化录入：把口径、公式、过滤条件以可执行规则写入数据源记忆，而不是塞进自由文本
多规则并存与自动并列：同一数据源支持多套口径共存（如本文的 Sales / Finance ）， Agent 自动识别并并列输出
跨会话自动加载：无需 prompt 工程、无需 attach 历史，新会话第一次问就生效
跨用户共享：同数据源下所有用户共用同一份记忆，避免团队内口径漂移
Agent 主动交叉校验：在多口径并存时， Agent 会基于已有规则主动追加校验逻辑（如本文的回款率 + 跨季归因）

如果你也在做反复回到同一份数据的工作——周报、月报、季度复盘、客户报告、对内对外的指标解释——不妨就试一次：

1.
第一次跑透：把这次的分析做完整，让 Agent 把业务定义跟你对齐
2.
沉淀进数据源：把对齐好的两三条口径写进数据源记忆，只需写一次
3.
下次直接问：换个会话、换个人、换个月份，同一句话直接问回去，看 Agent 是不是已经"知道你在说什么"

那一刻你会明白，过去那些"每次都要重新解释一遍业务"的日子，不是在用 AI 分析数据，而是在反复给 AI 做岗前培训。
